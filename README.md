# Распределение вычислительной нагрузки в многопроцессорной системе (MVS)

**Автор:** Даниил Жедек  
**Язык:** Python 3  
**ОС:** Linux (Ubuntu 24.04), также работает через WSL  

---

## Описание задачи

Рассматривается многопроцессорная вычислительная система с одинаковыми процессорами, соединёнными сетью. Задан набор программ, каждая из которых:

- создаёт фиксированную нагрузку на процессор (в процентах);
- может обмениваться данными с другими программами с заданной интенсивностью (Кбайт/с).

### Цель

Распределить программы по процессорам так, чтобы:

1. Суммарная нагрузка на каждый процессор не превышала **100 %**.
2. Суммарная нагрузка на сеть (от программ, работающих на *разных* процессорах) не превышала предела `net_limit`.
3. Минимизировать **максимальную нагрузку на процессор** (целевая функция).

---

## Допустимые значения

Используются в генераторе и проверяются при чтении входного файла:

- Нагрузка на процессор: `4`, `11`, `14`, `21` %
- Интенсивность обмена: `0`, `21`, `49`, `71`, `99` Кбайт/с
- `net_limit` — неотрицательное целое число, **кратное 100**

## Генерация входных данных
``` Bash
python3 generate_input.py <число_процессоров> <выходной_файл.xml>
```

Пример:

``` Bash
python3 generate_input.py 8 input8.xml
```

Генератор автоматически обеспечивает:

- среднюю загрузку процессора ≥ 40 %
- минимум две связи на каждую программу
- использование всех допустимых нагрузок и интенсивностей
- корректную структуру XML

## Последовательный алгоритм (mvs.py)
``` Bash
python3 mvs.py <входной_файл.xml>
```
Алгоритм останавливается, если за 5000 попыток подряд не найдено улучшение.

Вывод при успехе
``` text
SOLVED
<число итераций>
<распределение программ>
<значение целевой функции>
```

Вывод при неудаче
```text
FAILED
<число итераций>
Номера процессоров в выводе начинаются с 1
(внутреннее представление — с 0).
```

---

## Параллельный алгоритм (mvs_dop.py)
```Bash
python3 mvs_dop.py <входной_файл.xml>
```

Проводится сравнение двух подходов:

- Random — обычный параллельный случайный поиск
- Clustering — используется предварительное распределение на основе кластеризации
Для числа процессов 1, 2, 4, 8 выполняется по 10 прогонов.

Измеряется:

- среднее время выполнения
- достигнутая максимальная нагрузка CPU

---

## Генерируемые графики
После выполнения создаются два файла:

1. chart.png — процентное изменение времени выполнения
2. quality_comparison.png — сравнение средней максимальной нагрузки CPU

## Формат входного XML
``` XML

<mvs>
  <processors>N</processors>
  <prog_count>M</prog_count>
  <net_limit>L</net_limit>

  <programs>
    <program id="1" load="14"/>
    <program id="2" load="11"/>
  </programs>

  <communications>
    <comm from="1" to="5" intensity="71"/>
  </communications>
</mvs>
```

---

## Ограничения
- id — от 1 до M, без пропусков
- load ∈ {4, 11, 14, 21}
- intensity ∈ {0, 21, 49, 71, 99}
- для каждой связи выполняется from < to
- net_limit кратен 100

## Теоретическое обоснование
Идея кластеризации основана на работе:

А.Н. Сальников, А.И. Майсурадзе, Д.Ю. Андреев
«Агрегирование и аппроксимация задержек для пар процессов в коммуникационной среде многопроцессорных систем».

Авторы предлагают группировать пары процессов со схожим поведением задержек при росте размера сообщения.
В данном проекте эта идея адаптирована для создания начального распределения, снижающего межпроцессорные обмены.

---

## Особенности реализации
- Используется модуль multiprocessing для реальной параллельности.
- В последовательной версии критерий остановки — 5000 неудачных попыток подряд.
- В параллельной версии каждый процесс работает независимо, обновляя общее лучшее решение.
- Результаты усредняются по 10 прогонам.
